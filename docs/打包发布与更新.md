# 打包发布与更新

本 Fork 的源码提交到 main，安装包仅放 GitHub Release。TGZ、ZIP、dist/ 不纳入 Git；不重写已有历史。vendor/ 和 renderer/ 是运行资源，继续随源码管理。

## 1. 确定版本并修改命令

先读 docs/index.md，检查 git status 和差异，不混入无关改动。普通发布使用新版本；仅首次补发没有标签和 Release 的当前版本时可以保留版本号。

```powershell
npm version 0.5.1 --no-git-tag-version
```

上面版本仅作下一版示例。该命令同步 package.json 与 package-lock.json。随后修改 README 安装、更新、本地下载示例中的标签与 TGZ 文件名，二者必须同时更新；历史验证记录不替换。

固定格式：

```text
https://github.com/Songyanglin-curious/dsh-mermaid-plus/releases/download/v<版本>/dsh-mermaid-plus-<版本>.tgz
```

本轮首次 Release 使用 0.5.0。Release 附件未公开前，不声称安装地址已可用。

## 2. 检查与打包

所需工具：Node.js、npm、Git；浏览器测试还需 Chrome/Chromium。先列出本机实际路径。GitHub Actions 使用 Node 22，自带 gh；本机无需安装 gh。

```powershell
npm ci
npm test
node test/run-e2e-headless.mjs
node tools/pack-check.mjs
npm pack
git diff --check
```

逐条运行，失败即停止发布。只有 Mermaid 依赖变更时，先运行 npm run build 更新运行时。包清单应包含 renderer/ 和 vendor/，不含测试、工具或其他安装包。不要用 git add -f 提交 TGZ。

## 3. 提交与推送

限定暂存本次相关文件，检查暂存差异。提交信息使用中文。

```powershell
git add -- <本次相关文件>
git diff --cached --check
git diff --cached --stat
git commit -m '调整打包发布与安装说明'
git push origin main
git tag v0.5.0
git push origin v0.5.0
```

标签替换为实际版本，不移动已有公开标签。先确认源码推送成功，再推标签。SSH 连接故障时可以使用相同仓库的 HTTPS URL 推送，不必修改 origin；凭据使用现有 Git 凭据管理器，不写入仓库或输出。

## 4. Release 自动发布

.github/workflows/release.yml 在 v* 标签推送后执行现有单元、浏览器、包清单检查，并核对标签与 package.json 版本。打包到 dist/，生成 SHA256SUMS.txt，上传 TGZ 与校验文件到草稿 Release，上传成功后公开。无需 NPM_TOKEN，不发布 npm。

手动运行工作流只检查并保留 Actions artifact，不创建 Release。标签工作流失败时先看失败步骤；未公开的草稿不视为发布完成。附件已存在时不要盲目重跑创建步骤或覆盖公开版本，先核对现状。

## 5. 发布回验与安装更新

回读 main、标签指向和工作流结果。打开对应 Release，确认非草稿、TGZ 名称和版本一致，且附有 SHA256SUMS.txt。从 README 同一下载地址下载两份文件，用 Get-FileHash -Algorithm SHA256 核对；检查归档内版本和运行文件。

```powershell
dsh plugin --profile web add https://github.com/Songyanglin-curious/dsh-mermaid-plus/releases/download/v0.5.0/dsh-mermaid-plus-0.5.0.tgz
dsh plugin --profile web list
```

已安装同名插件时，先执行 dsh plugin --profile web remove dsh-mermaid-plus，再安装目标版本。重启对应 Profile、刷新页面并确认实际版本；发布不会自动更新本机。其他 Profile 替换 web，回退使用旧 Release 的固定版本 URL。

交付说明须分别报告源码提交、Release 链接、下载回验结果与本机是否更新。工作流或远程安装未验证时如实注明。
